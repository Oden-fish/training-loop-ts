テストコードを書くときの制約:

- **実装より先に書き、落ちることを確認してから実装に進む。** 通ってしまったテストは、
  受け入れ条件を検証していない可能性が高い。
- アサーションは「壊れたら落ちる」ものにする。`toBeDefined()` や `assert result` だけで終わらせない。
- モックは外部境界（ネットワーク、時刻、ファイルシステム）だけ。自分のコードをモックしない。
- 1テスト1事象。名前は「何が / どういう条件で / どうなる」が読み取れる形にする。
- 既存テストを「通すために」書き換えない。仕様変更で必要なら、その理由を PR 本文に書く。
